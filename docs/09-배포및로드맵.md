# 09. 배포 준비 및 로드맵 상세

> **범위 변경 (2026-09-21)**: Gmail 단독 지원으로 한정됨에 따라 네이버 연동 단계를 로드맵에서 제거하고 이후 단계 번호를 재정렬했다. 또한 MVP는 LLM을 사용하지 않기로 결정해 1단계 기간을 단축하고 LLM 관련 블로커를 제거했다 (`00-개요.md`, `02-쿠폰판별로직.md` 참고).

원본 설계의 "앱스토어/플레이스토어 배포를 위한 사전 준비사항"과 "개발 로드맵 및 마일스톤"을 실행 체크리스트 수준으로 정리한다.

## Google OAuth 심사 준비 체크리스트 (상세)

- [ ] **[지금 착수]** GCP 프로젝트 생성 및 OAuth 동의화면 구성 (앱 이름, 로고 512x512, 지원 이메일)
- [ ] **[지금 착수]** 개인정보처리방침 URL 준비 (07번 문서 내용을 기반으로 법무 검토 후 게시)
- [ ] **[지금 착수]** 서비스 이용약관 게시
- [ ] **[2단계 완료 후]** 데모 영상 제작 — 심사관이 앱의 실제 Gmail 접근 목적을 이해할 수 있도록 온보딩부터 쿠폰 알림 수신까지 전 과정을 화면 녹화 (2~3분 분량 권장)
- [ ] **[지금 착수 — 초안]** 보안 백서 작성 — 07번 문서의 암호화/토큰 폐기/데이터 보관 정책을 정리한 문서
- [ ] **[최우선]** CASA 심사 대상 여부 **및 비용** 확인 후, 해당 시 07번 문서의 CASA 체크리스트 진행 시작 — 전체 일정의 병목이자 예산 변수이므로 다른 착수 작업보다 먼저 확인한다
- [ ] **[3단계]** 미검증(unverified) 상태로 테스트 사용자 100명 등록 후 내부 베타 진행

## 스토어 배포 체크리스트

- [ ] Apple App Store: App Privacy 설문지 작성 (수집 데이터 유형: 이메일 메타데이터, 연락처 아님 명시 등 정확히 기재 — 부정확한 신고는 반려 사유가 됨)
- [ ] Apple: 백그라운드 메일 접근에 대한 심사 코멘트 사전 작성 (심사관이 계정 없이도 앱 목적을 이해하도록 설명 첨부, 테스트 계정 제공)
- [ ] Google Play: 민감 권한(계정 접근) 관련 Data Safety 섹션 작성

## 개발 로드맵 (원본 기준 + 세부 산출물 매핑, 네이버 연동 단계 제외)

| 단계 | 기간 | 목표 | 이번 상세 설계 문서와의 매핑 |
| --- | --- | --- | --- |
| 1. MVP 백엔드 | 1–2주 | Gmail OAuth 연동, webhook 기반 감지, 규칙 기반 판별 파이프라인 (LLM 미사용) | 01, 02, 03, 05번 문서 기준으로 구현 |
| 2. 모바일 앱 프로토타입 | 2–3주 | 온보딩/목록 화면, FCM 연동, Gmail 내부 테스트 | 04, 06번 문서 기준 |
| 3. 내부 베타 (Closed Test) | 2–4주 | 판별 정확도/오탐지율 측정, 규칙 보정 | 02번 문서 "운영 중 정확도 측정 방법", 08번 문서 알림 기준 적용 |
| 4. Google OAuth 보안 심사 제출 | 4–8주(대기) | 백서, 데모 영상 제출 | 07번 문서 CASA 체크리스트, 위 스토어 체크리스트 |
| 5. 심사 대기 중 마무리 | 심사와 병행 | 스토어 제출 준비, 모니터링 구축 | 05번 문서 로깅/모니터링, 08번 문서 알림 기준 |
| 6. 정식 출시 | 심사 통과 후 | 점진적 롤아웃 10% → 50% → 100% | - |

네이버 연동 단계가 빠지면서 전체 일정이 1~2주 단축되고, 네이버 관련 법무 검토라는 블로커도 함께 사라졌다.

## 착수 전 블로커 (2026-09-21 전건 확정)

착수 전 확정을 권장했던 블로커 3건을 모두 결정했다.

1. **(해결됨) LLM 벤더/모델 확정** — MVP는 LLM을 사용하지 않기로 결정해 해소됨 (`00-개요.md`, `02-쿠폰판별로직.md` 참고)
2. **(해결됨) Google OAuth 심사 착수 시점 — 단계 분할 착수** — 심사 요건 중 실제 동작하는 앱이 필요한 것은 데모 영상뿐이고 나머지는 앱 없이 준비 가능하므로, 1단계와 병행해도 재작업 리스크가 낮다고 판단했다.
   - **지금 착수**: GCP 프로젝트/동의화면 구성, 개인정보처리방침·이용약관 게시, 보안 백서 초안, CASA 대상 여부·비용 확인
   - **2단계(모바일 앱 프로토타입) 완료 후**: 데모 영상 촬영 → 심사 제출
   - 위 "Google OAuth 심사 준비 체크리스트"의 각 항목에 착수 시점을 표기해뒀다.
3. **(해결됨) 초기 지원 발신자 목록 — 목록이 아니라 선정 절차를 확정** — 지금 근거 없이 10곳을 찍으면 헛수고가 될 가능성이 크고, 전용 파서는 실제 메일 샘플이 있어야 정규식을 작성할 수 있다. 따라서 "실제 메일함 집계 → 카테고리 슬롯 배분" 절차만 확정하고 목록 자체는 1단계 착수와 동시에 데이터로 채운다. 절차는 `02-쿠폰판별로직.md` "초기 지원 발신자 선정 절차" 참고. 1단계와 병행 가능하므로 더 이상 블로커가 아니다.

**남은 확인 사항 (결정이 아니라 사실 확인)**: CASA 심사 대상 여부와 비용. `gmail.readonly`는 restricted scope이므로 대상이 될 가능성이 높고, Tier 2 평가는 외부 심사 기관 비용이 발생한다. 결과에 따라 위 로드맵 4단계의 기간과 비용 계획을 다시 손봐야 한다.

## 단계별 완료 정의(Definition of Done) 제안

각 단계 종료 시 다음을 충족해야 다음 단계로 진행:

- 1단계: 테스트 Gmail 계정으로 실제 프로모션 메일 수신 → DB에 `coupons` 레코드 생성까지 end-to-end 확인
- 2단계: 테스트 기기에서 실제 푸시 알림 수신 → 탭 시 상세 화면 진입까지 확인
- 3단계: 08번 문서의 알림 기준(에러율 등)이 베타 기간 중 임계치를 초과하지 않음을 확인
