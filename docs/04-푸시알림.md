# 04. 푸시 알림 발송 상세 설계

원본 설계의 "푸시 알림 발송 설계" 섹션을 구체화한다. DB 스키마는 03번 문서(`devices`, `notifications` 테이블)를 따른다.

## 발송 흐름

```
쿠폰 판별 완료 (usable_now=true)
  → coupons 레코드 생성
  → push-dispatch 큐에 PushDispatchJob 적재
  → NotificationService가 잡 소비
      1. 사용자의 notifications_enabled 확인 → false면 notifications.send_status='skipped_disabled'로 기록 후 종료
      2. 사용자의 활성 devices 전체 조회 (다중 디바이스 = 전체 발송 정책, 00번 문서 결정 #2)
      3. 각 디바이스에 대해 notifications 레코드 생성 (status='pending')
      4. FCM/APNs로 발송 요청
      5. 응답에 따라 send_status를 sent/failed로 갱신
```

## 플랫폼별 발송 방식

- Android: FCM HTTP v1 API 직접 사용
- iOS: FCM이 내부적으로 APNs를 중계하는 방식 채택 (원본 설계에서 언급한 통합 방식) — React Native 사용 시 `@react-native-firebase/messaging`으로 클라이언트/서버 모두 FCM 하나의 SDK로 통일 가능해 유지보수 부담이 적음
- 별도로 APNs 직접 연동(예: 리치 알림, 알림 확장 등 고급 기능)이 필요해지면 2단계에서 검토

## 알림 페이로드 최종안

```json
{
  "token": "<fcm_token>",
  "notification": {
    "title": "새 쿠폰 도착",
    "body": "쿠팡 15% 할인 쿠폰 · 9/30까지 사용가능"
  },
  "data": {
    "type": "new_coupon",
    "couponId": "c_8823",
    "deeplink": "myapp://coupons/c_8823"
  },
  "android": {
    "priority": "high"
  },
  "apns": {
    "headers": { "apns-priority": "10" },
    "payload": { "aps": { "sound": "default" } }
  }
}
```

- `emailId`, `expiryDate` 등 원본 설계에 있던 필드는 `data.couponId`로 앱이 `/coupons/:id`를 조회해 상세 정보를 가져오는 방식으로 단순화했다. 페이로드에 만료일 등 민감할 수 있는 세부 정보를 중복 포함하지 않아 페이로드 크기(FCM 4KB 제한)와 정보 노출 범위를 모두 줄인다.
- `notification_type='expiry_reminder'`인 경우 `title`을 "쿠폰 만료 임박"으로, `body`에 D-day를 강조 (예: "쿠팡 15% 할인 쿠폰 · 오늘 자정 만료").

## 다중 디바이스 발송 정책 (2026-09-21 확정)

한 사용자가 여러 기기에 로그인한 경우 **모든 활성 디바이스에 발송**한다. "가장 최근 기기 1대에만 발송"하는 대안도 검토했으나, 개인 사용자는 대부분 기기가 1대라 실질 차이가 없는 반면 기기를 교체한 직후 알림이 끊기는 실패 모드가 더 나쁘다고 판단했다. 중복 수신에 대한 우려는 아래 토큰 수명주기 정책(무효 토큰 즉시 삭제, 90일 미접속 정리)으로 충분히 통제된다고 보고 기기 수 상한은 두지 않는다.

## 디바이스 토큰 수명주기

| 이벤트 | 처리 |
| --- | --- |
| 앱 최초 실행/로그인 | `POST /devices`로 등록 |
| 클라이언트가 FCM 토큰 갱신 감지 (`onTokenRefresh`) | 기존 레코드 갱신 (`fcm_token` UPDATE, `last_active_at` 갱신) |
| 발송 응답이 `UNREGISTERED`/`NotRegistered` | 해당 `devices` 레코드 즉시 삭제, 이후 발송 대상에서 제외 |
| 사용자 로그아웃 | `DELETE /devices/:id` 호출 |
| 90일 이상 미접속 디바이스 | 배치 작업으로 정리(soft delete 또는 삭제) — 저장 비용 및 무효 발송 방지 |

## 재시도 및 실패 정책

- 발송 실패(네트워크 오류, 일시적 5xx) 시 지수 백오프로 최대 3회 재시도: 1분 → 5분 → 15분 간격
- 3회 모두 실패하면 `notifications.send_status='failed'`로 최종 기록, 알림 손실을 감수 (쿠폰 자체는 앱 내 목록에서 여전히 확인 가능하므로 치명적이지 않음)
- `UNREGISTERED` 등 영구 실패 응답은 재시도하지 않고 즉시 실패 처리 + 토큰 삭제

## 알림 설정 세분화 (원본 대비 확장)

원본은 단순 on/off 토글만 언급했으나, `notifications` 테이블에 `notification_type`을 두었으므로 설정도 세분화를 권장한다.

- 신규 쿠폰 알림 on/off
- 만료 임박 리마인더 on/off
- (베타 이후 검토) 특정 발신자/브랜드별 알림 음소거

## 발송량 모니터링

- 일별 발송 성공/실패 건수, 평균 발송 지연시간(메일 도착 → 푸시 발송까지)을 Cloud Monitoring 대시보드에 노출 — 원본 설계의 "성공 기준: 수 분 이내 알림 전달"을 실제로 측정 가능하게 함
